# ADR-0011: 同梱 ggml にパッチを当て、Metal が FP8 の行列積を断るようにする

- Status: Accepted
- Date: 2026-11-13

## Context

stable-diffusion.cpp `master-1090` は、safetensors の FP8 テンソル（dtype `F8_E4M3` / `F8_E5M2`）を
1 要素 1 バイトのまま保持する。その重みとの行列積の前に、バックエンドへ「この積を計算できるか」を
尋ね、できないと答えられたら、その呼び出しのあいだだけ重みをキャストする。

sd.cpp が同梱する ggml の Metal バックエンドは「できる」と答えるが、そのためのカーネルを持たない。
最初の積でプロセスが異常終了する。この版で実測したこと:

- `t5xxl_fp8_e4m3fn` を読む FLUX と SD3.5 の生成が、すべて異常終了した。
- テンソル 1 つ（`time_embed.0.weight`）だけを FP8 にしたチェックポイントも異常終了した。

最初の対処は同梱ツリーの外に留めた。image-forge が `tensor_type_rules` を通じて、FP8 の
コンポーネントを読み込み時に F16 へ変換するよう sd.cpp に指示した。これでカタログの FLUX と
SD3.5 は直った。取りこぼしはリリース前の検証が見つけ、実測で確かめた。sd.cpp は一部のテンソル
（入出力の層、時刻埋め込み、埋め込み表）をどの変換ルールからも除外するため、利用者が取り込んだ
FP8 チェックポイントではそれらが FP8 のまま残り、v0.30.0 では生成できたものが異常終了した。
このルールは設定された `wtype` も上書きしていた。

原因は ggml の Metal バックエンドの関数 1 つにある。image-forge が sd.cpp に渡すものは、そこへ
届かない。

## Decision

- 同梱 ggml に**ローカルパッチを 1 本**持つ:
  `third_party/patches/0001-ggml-metal-decline-fp8-mul-mat.patch`。
  `ggml_metal_supports_mul_mat_op` が FP8 の重みに対して false を返すようにし、sd.cpp 自身の
  代替経路を働かせる。ほかは何も変えない。変換ルールは取り除く。
- パッチはこのリポジトリのファイルとして持ち、`third_party/patches/series` に、適用する順と
  適用先のディレクトリを並べる。submodule のポインタは、手を入れていない上流のコミットを
  指したままである。
- `make deps` はエンジンのビルドのたびに走る。パッチを当て（`scripts/vendor-patches.sh apply`）、
  何が古いかの判断は cmake に任せる。ポインタが動いた場合も、パッチが変わった場合も、パッチより
  前に作られたライブラリも、そのままリンクされずに作り直される。
- `scripts/vendor-patches.sh verify`（`make verify-vendor`）はエンジンのビルドのたびに走る。
  同梱したチェックアウトと、その中のすべての submodule が対象である。それぞれが、親の記録する
  コミットの上にあり、追跡されていないファイルを持たず、そのコミットとの違いがパッチの分だけで
  あること（同じファイルに同じ行数。パッチのないディレクトリでは違いが無いこと）を確かめ、
  そうでなければ失敗する。同梱ツリーのどこかへの手編集、series から外したのにツリーに残っている
  パッチ、ツリーを説明しなくなったパッチは、ビルドを止める。比べているのはファイル名と行数で
  あって内容ではない。パッチがすでに変えている行の範囲に収まる編集は見えない。
- submodule は `.gitmodules` で `ignore = dirty` とする。作業コピーが、固定したコミットと常に
  異なるようになるためである。その結果、ビルドに名前を付ける `git describe --dirty` は同梱ツリーの
  状態を映さなくなる。ポインタそのものは引き続き追跡され、中身は `verify` が見張る。
- パッチ 1 本が判断 1 つ、ADR 1 本に対応する。2 本目には 2 本目の ADR を書く。

## Consequences

- FP8 の重みはメモリ上で 1 バイトのまま保持され、呼び出しのたびにキャストされる。FLUX の
  ピークメモリは、読み込み時に F16 へ広げていた v0.30.0 より小さい。
- stable-diffusion.cpp のポインタを動かす手順は決まっている: `vendor-patches.sh revert`、
  ポインタを動かす、`make deps`。パッチが当たらなくなっていればビルドが止まり、そう告げる。
  そのときにすることは、上流がバックエンドを直したかを確かめて（パッチを外して `flux1-schnell` を
  生成する）パッチを捨てることであり、無理に当てることではない。
- パッチの適用先は submodule の中の submodule である。パッチが当たっているあいだの
  `git submodule update --recursive` は、そのツリーを動かすことを拒むか（新しいコミットがパッチ先の
  ファイルに触れているとき）、編集を確かめずに持ち越す。先に revert して、判断を `apply` に任せる。
- 不具合は上流のものである。上流へ報告するかどうかはリポジトリの所有者が決める。この ADR は
  それに依存しない。

## Alternatives considered

- **ルールで変換しきれない FP8 ファイルを拒否する。** 異常終了はなくなるが、v0.30.0 で使えた
  チェックポイントが使えなくなる。sd.cpp の除外リストの写しを image-forge が持つことになり、
  ずれていく。
- **読み込み前に FP8 ファイルを F16 の複製へ変換する。** 同梱ツリーに触れず v0.30.0 と同じ結果に
  なるが、ディスクに複製が増え（5 GB の T5 で約 10 GB）、変換の時間もかかる。
- **`SD_USE_UPSTREAM_GGML` でビルドする。** 読み込み時に FP8 を変換するようにはなるが、sd.cpp
  独自の Metal 拡張と INT8 の経路も無効になる。
